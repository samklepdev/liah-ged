# LIAH HSD — Design Spec

Date: 2026-11-18
Status: Approved for planning

## Summary

LIAH HSD is a high-school-diploma learning platform, forked from the existing
`liah-learning` project (LIAH International Academy). It reuses that app's
architecture and features wholesale — auth, roles, catalog/quiz-taking,
progress tracking, profile, admin console — rebranded under a new visual
identity ("The Registrar"), with one new feature: a downloadable diploma
certificate issued once a student has passed every subject.

Quiz content (subjects/courses/questions) is **out of scope** for this pass.
The schema and UI must be ready to hold it; the content itself arrives later,
the same way LIAH Learning's content arrived after the app was built (see
`Quiz Content Pipeline` in the agent wiki).

## Starting point

Fork, not a rewrite. Copy `liah-learning`'s `backend/` and `frontend/`
workspaces into this repo (`liah-hsd`), keeping:

- npm workspaces monorepo (`backend`, `frontend`), run together with
  `concurrently`
- Express 5 + TypeScript, Drizzle ORM, PostgreSQL, Argon2 password hashing,
  Zod validation
- React 19 + TypeScript + Vite, React Router, Vitest + Testing Library
- Docker Compose for local Postgres (own container name/port to avoid
  colliding with `liah-learning`'s `liah-postgres` on `54330`)
- Vercel-style deployment shape (`vercel.json`, `SERVE_FRONTEND` SPA
  fallback) — unless the user later picks a different host

Everything under `backend/src/{routes,controllers,models,middleware,lib,
config,types}` and `frontend/src/{pages,quiz,admin,auth,shell,shared,lib}`
carries over structurally as-is. Diploma-specific changes layer on top
rather than restructuring.

## What carries over unchanged (feature-complete already)

- **Auth**: cookie-session login, Argon2 password hashing, change password,
  password-reset-request flow. No self-service registration (admin creates
  accounts), matching LIAH Learning's current state.
- **Roles**: exactly two — `user` and `admin`.
- **Catalog model**: Subjects → Courses → Quizzes. A `passScore` per course
  drives pass/fail; `attempt.model.ts`'s best-score-per-course logic is
  reused unchanged.
- **Quiz-taking**: attempt creation, grading, results/review, retakes.
- **Progress tracking**: per-subject and overall completion views.
- **Profile**: view/edit profile, change password.
- **Admin console**: user management, course/quiz import (including the
  PDF quiz-parser pipeline and its three dialects), attempt review.

## Rebrand

- Package/app metadata, page titles, and seed/admin-user scripts renamed
  from LIAH International Academy → **LIAH HSD** / "LIAH High School Diploma
  Program."
- Strip LIAH-International-Academy-specific copy and any seeded demo
  content; replace with a couple of placeholder subjects (e.g. "Mathematics,"
  "English Language Arts") so the UI has something to render pre-content.
- Apply the **Registrar** visual direction, approved from the three
  mockups presented during brainstorming:
  - Navy `#152542` primary, gold `#9c7a2e` accent, white ground, slate-grey
    (`#5a6378`) secondary text, light grey (`#dde1e8`) hairline borders.
  - Serif headings (system serif stack: Georgia / Iowan Old Style /
    Palatino Linotype), sans UI chrome (system sans stack) — the split
    signals "official document" vs. "application interface."
  - A circular seal mark (initials in a thin gold ring) used in the nav
    brand and on the certificate.
  - Hairline-rule card borders rather than heavy shadows; gold used sparingly
    for accents/status pills, not as a dominant fill.
  - This replaces LIAH Learning's existing theme tokens; component
    structure (cards, nav, forms) is reused, only the token values and
    heading font change.

## New feature: diploma certificates

**Trigger**: a certificate is issued once a student has passed (met
`passScore`) every course in every subject in the active curriculum — i.e.
full diploma completion, not per-subject. This is recomputed after each
quiz attempt is graded, reusing the existing best-score-per-course data;
no new "completion" tracking table is needed beyond the certificate record
itself.

**Data model** — new `certificates` table:

| column | type | notes |
|---|---|---|
| `id` | uuid/serial | pk |
| `user_id` | fk → users | one certificate per user (unique) |
| `issued_at` | timestamp | set once, never updated |
| `verification_id` | text, unique | short public code shown on the PDF (e.g. `LH-29F3-8841`) |

Issuance is **idempotent**: if a certificate already exists for the user,
re-checking eligibility is a no-op. A certificate, once issued, is never
revoked or regenerated by this pass (no "subject re-failed after
certification" handling — out of scope).

**Generation**: server-side PDF via a lightweight library (`pdfkit` or
equivalent already compatible with the Vercel serverless target), styled to
match the Registrar mockup — navy border, gold seal, student name, program
name, issue date, verification ID. Rendered on demand at download time from
the stored certificate row (no binary stored in Postgres).

**Routes**:
- `GET /api/certificates/me` — current user's certificate status: not
  eligible (with subjects remaining), eligible/issued (with download link),
  or not yet issued but eligible (triggers issuance check).
- `GET /api/certificates/:id/download` — authenticated, streams the PDF for
  the owning user (or admin).
- `GET /api/certificates/verify/:verificationId` — **public**, no auth;
  confirms a certificate's authenticity (name, program, issue date) for
  third parties checking it, without exposing the account.

**Frontend**: the existing Progress page gains a "Diploma Certificate" card:
- Locked state: "X subjects remaining" (reuses existing progress data).
- Unlocked state: download button, verification ID shown, matching the
  certificate mockup's layout.

## Error handling

- Certificate issuance check runs inside the same transaction as attempt
  grading where feasible; a failure to issue (e.g. PDF step) must not fail
  the quiz submission — issuance is retried lazily on next `GET
  /api/certificates/me` call rather than blocking grading.
- `verify/:verificationId` with an unknown code returns 404 with a generic
  "not found" body — no information disclosure about valid ID shapes.
- Download route returns 403 if the authenticated user isn't the
  certificate's owner and isn't an admin.

## Testing

- Carry over existing `node:test` (backend, `tsx`, `--test-concurrency=1`)
  and Vitest + jsdom (frontend) conventions and fixtures approach.
- New unit tests: certificate-eligibility calculation (all-passed vs.
  one-remaining vs. zero-progress), idempotent issuance (calling the check
  twice yields one row).
- New integration test: full flow — seed a user who has passed every
  course, hit `GET /api/certificates/me`, confirm issuance, download the
  PDF, verify via the public endpoint.
- Typecheck convention (`tsc` separate from `tsx`-run tests) carries over
  unchanged.

## Out of scope for this pass

- Actual diploma curriculum content (subjects/courses/quiz questions) —
  arrives later via the same PDF-parsing pipeline, once source material
  exists.
- Per-subject certificates (only the single full-diploma certificate).
- Certificate revocation/regeneration after issuance.
- Any grade-level (9th–12th) layer in the catalog — the model stays
  Subjects → Courses → Quizzes, same as LIAH Learning.
- Self-service registration (stays admin-provisioned, matching LIAH
  Learning's current state).
- Choice of production host — reuse LIAH Learning's Vercel shape for now;
  revisit if that's not where this ends up deployed.
